### 3. 受講生一覧の「通し番号」列を「受講者番号」に置き換え（PR #52、追加分）
decision-maker の質問「受講生一覧の通し番号が無い（全員 `-`）のは問題か」に対応。

- **原因**: 令和8年度は出欠管理名簿から Firestore へ直接同期する新経路（PR #33）で、名簿に通し番号の列が無く `serial_number` が常に 0 になる。Dashboard は 0 を `-` で表示していた。バグではなく令和8年度の仕様変更に伴う状態
- **判断**: decision-maker の指摘「通し番号とは名簿の受講者番号（A001 形式）のことでは」を受け、`student_number`（名簿の受講者番号、グループをまたいだ連番。取り込みスクリプトも 1..N の連番を検証済み）に置き換える方針で合意。置き換えの指示は decision-maker から明示
- **変更**: 受講生一覧・グループ別一覧・カード表示の表示と並べ替えを `serial_number` → `student_number` に変更、見出しを「受講者番号」に。並べ替えは `localeCompare(..., { numeric: true })`。対象外: `DuplicatesView.vue`（シート由来の重複検出用の別表示）、`StudentDetailView.vue`（すでに受講者番号を表示）。BE・Firestore ルール・スキーマの変更なし
- **レビュー**: codex review は medium・high とも指摘 0 件。Claude 系（code-reviewer・pr-test-analyzer）の指摘「fixture が同桁の A001〜A005 だけで `numeric: true` を外しても通る」を採用し、A9/A10 の桁またぎと空の番号のテスト、カードの「-」が受講者番号のセルだけであることのテストを追加（表側の見出し・セルのテスト不足は既存の穴で対象外）
- **本番確認**（デプロイ後、Playwright）: 受講生一覧 254人全員に A001〜R254、降順で R254→A001。グループ別一覧（A グループ）17人に A001〜A017、降順 A017→A001。390px のカードに「受講者番号 A017」等が表示され崩れなし

### レビューで分かったこと
- `pr-test-analyzer`（静的検証）は、PR #45 では「CI で落ちる要因なし」と報告したが実際は4件失敗した（`happy-dom` 12.10.3 が、キー付きリストの並べ替えで要素を末尾へ移動すると `children` / `querySelectorAll` を古いまま返す不具合。`src/test/dom.ts` で回避）。PR #48 では「CI で落ちる可能性が高い」と指摘された2点が実際の CI では pass だった。**静的レビューの見立ては CI の代わりにならない**（どちらの方向にも外れる）
- PR #48 のレビューで、日介番号が空の提出ファイル（バックエンドは解析できないと空文字で保存する）が黙って捨てられ「全員未提出」と表示される穴を3者が指摘。実在を確認して修正済み
- PR #52 のテスト分析で、rename のためにテストの値を機械的に置換すると、変更の中心（数値比較）を検証しないテストが残ることが分かった（`numeric: true` を外しても全テストが通る状態だった）。値の置換後は「この変更で一番壊れやすい点をテストが検出できるか」を確認する
- PR #48 で「マージ後の本番実測で未達が判明」した。設計時に「並列取得は総時間を縮める」と考えたが、回線を分け合ってカードの表示を遅らせることは、実測するまで見積もれなかった
