## 🎯 目的

2ページ目以降のページ遷移後の待機時間を延長し、テーブル要素のロード完了を確実に待つことで、タイムアウトエラーを解消します。

## 📋 問題の詳細

### 発生したエラー

**2025-11-03 17:26 JST実行時**:
```
Error extracting submissions: Timeout 30000ms exceeded.
  File "/app/src/playwright_automation.py", line 423, in get_submission_list
    list_frame.wait_for_selector("tr.standard_grid_item", timeout=30000)
```

### 問題の経緯

1. **早期重複チェック実装後の初回テスト**:
   - 1ページ目: ✅ 正常処理（100件、86件重複検出）
   - 2ページ目: ❌ テーブルセレクタ待機でタイムアウト

2. **処理フロー**:
   ```
   17:25:55 - Processing page 2
   17:26:01 - Performing early duplicate check for 55 submissions  ← 早期チェック開始
   17:26:14 - Error: Timeout 30000ms exceeded  ← 30秒後にタイムアウト
   ```

3. **根本原因**:
   - ASP.NET `__doPostBack`によるページ遷移後、3秒待機
   - しかし、早期重複チェック（Firestoreクエリ）により処理時間が増加
   - Firestoreチェック後にテーブル要素を探すと、既に30秒のタイムアウトに達する

### 待機時間の現状

| ページ | 現在の待機時間 | 問題 |
|--------|--------------|------|
| 1ページ目 | 5秒（frame reload後） | ✅ 問題なし |
| 2ページ目以降 | 3秒（page transition後） | ❌ 不足（早期チェック考慮なし） |

### タイムライン分析

**2ページ目の処理**:
- `17:25:55`: ページ遷移開始 → 3秒待機
- `17:25:58`: テーブル要素待機開始（`wait_for_selector`、30秒タイムアウト設定）
- `17:26:01`: 早期重複チェック開始（55件）
  - Firestoreクエリ: 55件 × 約0.03秒 = 約1.7秒
- `17:26:03`: 早期重複チェック完了（推定）
- `17:26:14`: テーブル要素待機タイムアウト（30秒経過）← **問題発生**

**推定原因**:
- 早期重複チェックの実装により、テーブル要素待機の**前**にFirestoreクエリが実行される
- Firestoreクエリ中にテーブル要素のタイムアウトカウントが進行
- 結果的に、実質的な待機時間が不足

## 🎯 修正方針

### アプローチ: 待機時間の延長（保守的）

**変更内容**:
- 2ページ目以降の待機時間: **3秒 → 5秒**

**理由**:
1. **シンプル**: 最小限の変更で問題解決
2. **安全**: 1ページ目と同じ待機時間に統一
3. **実績あり**: 1ページ目は5秒で問題なく動作

**代替案（採用しない理由）**:
- 動的待機（要素出現まで待つ）: 複雑化、デバッグ困難
- Firestoreチェックの非同期化: 大規模な設計変更が必要

## 📝 実装計画

### 変更ファイル: `src/playwright_automation.py`

**変更箇所**: lines 406-410

**Before**:
```python
elif current_page > 1:
    # Page transition via ASP.NET __doPostBack
    logger.info("Waiting for table to render after page navigation...")
    time.sleep(3)
```

**After**:
```python
elif current_page > 1:
    # Page transition via ASP.NET __doPostBack
    # Extended wait time to 5 seconds (same as page 1) to ensure table rendering
    # completes before early duplicate check begins
    logger.info("Waiting for table to render after page navigation (5 seconds)...")
    time.sleep(5)
```

### ログの改善

**追加ログ**:
- 待機時間の明示（5秒）
- 早期重複チェック前後のタイミングログ
