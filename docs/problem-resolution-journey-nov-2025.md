### 📅 Phase C: Iframe Context問題（2025-11-08 00:00-00:30 JST）

**問題の継続**:
- Phase B修正後も Page 2+ 学生が失敗
- **症状**: ダウンロードリンクが見つからない

**根本原因**:
1. **DOWNLOAD_LINK定数が未定義**
   - `CarewellSelectors.DOWNLOAD_LINK` が存在しない

2. **Iframe context エラー**
   - 詳細ページが iframe 内にロードされる
   - メインページのコンテキストで検索 → 失敗

3. **エラー後の go_back() 欠如**
   - TimeoutError / Exception 発生時に詳細ページに留まる
   - 次の学生処理が失敗

**対応**:
1. `DOWNLOAD_LINK = 'a[href^="download.aspx"]'` を追加
2. 詳細ページ遷移後、iframe 参照を更新
3. 全エラーハンドラに `go_back()` 追加

**コミット**:
- `054614c`: Add iframe refresh and error recovery

**成果**:
- Page 2+ 学生の成功率: 0% → **一部成功**

### 📅 Phase D: パラメータ名の誤り（2025-11-08 00:30-01:00 JST）

**問題の継続**:
- 一部の学生がまだ失敗

**根本原因**:
- **パラメータ名の推測ミス**: `Sid` → 実際は `log_id`
- 実際のHTML構造を確認せずにコーディング

**実際のHTML**:
```html
<a href="report.aspx?log_id=7451&unit_id=684&course_id=41&filter=all">
  川久保　晃 <N9903754>
</a>
```

**対応**:
- すべての `Sid` 参照を `log_id` に変更（5箇所）
- 正規表現修正: `r"Sid=(\d+)"` → `r"log_id=(\d+)"`

**コミット**:
- `ae5d169`: Replace Sid parameter with log_id

**成果**:
- Page 2+ 学生の成功率向上

**教訓** (CLAUDE.md Common Mistake #10):
> "NEVER guess parameter/field names without verification"

### 📅 Phase E: 最適化の設計ミス（2025-11-08 22:00-23:25 JST）

**新たな問題発生**:
- 最適化コミット `bbd61ab` 後、**致命的な退行**
- **症状**: 1人目のみ成功、2人目以降**全員失敗**

**根本原因**:
- `go_back()` を Page 2+ でスキップ（タイムアウト回避目的）
- **誤った仮定**: "スキップしても次の処理に影響ない"
- **実際**: `go_back()` は詳細ページ→リストページへの**唯一の手段**

**問題のコード** (bbd61ab):
```python
if current_page > 1:
    self.logger.info(f"[PHASE 1] Skipping go_back() for Page {current_page}")
    # → 詳細ページに留まる
    # → 次の学生処理時にpagination control見つからず失敗
else:
    self.page.go_back(wait_until="domcontentloaded", timeout=180000)
```

**影響**:
```
学生A（1人目）: 詳細ページ → go_back() スキップ → 詳細ページ留まる
学生B（2人目）: STEP 1 開始 → 詳細ページのまま → pagination control 無し → 失敗
学生C以降: 同様に全員失敗
```

**成功率**: **0.5% (1/200)**

### 📅 Phase F: 正しい最適化の実装（2025-11-08 23:40 JST）

**修正方針**:
- ❌ スキップ（処理を省く）
- ✅ タイムアウト短縮（180秒 → 30秒）

**修正内容**（コミット `6e39cce`）:

3箇所の `go_back()` 処理を統一:

```python
# ✅ 正しい最適化
try:
    self.page.go_back(wait_until="load", timeout=30000)  # 180s → 30s
except Exception as e:
    self.logger.warning(f"[PHASE 1] go_back timeout expected: {e}")

self._wait_for_navigation()
```

**変更点**:
1. `if current_page > 1:` 条件削除 → 全ページで実行
2. `timeout=180000` → `timeout=30000` (83% 削減)
3. `wait_until="domcontentloaded"` → `wait_until="load"` (より確実)
4. Success / TimeoutError / Exception の3パスすべてで統一

**成果**:
- **Phase 1**: 200/200 成功 (100%)
- **Phase 2**: 45-46/49 成功 (92-94%)
- **処理時間**: 600分 → 100分 (83% 削減)

**検証時刻**: 2025-11-08 23:51 JST

**教訓** (CLAUDE.md Common Mistake #11):
> "タイムアウト回避のために必須処理をスキップしてはいけない"
