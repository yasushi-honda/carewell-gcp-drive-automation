### 3. 主要な学習ポイント

#### タイムアウトエラーの根本原因パターン

```
タイムアウトエラーが発生
  ↓
1. フレームは有効か？
   NO → フレーム再取得を追加（Phase 3.5パターン）
   YES → 次へ
  ↓
2. セレクタ/検出ロジックは妥当か？
   NO → ロジックを修正（Phase 6パターン）
   YES → 他の要因を調査
```

#### CSS セレクタの落とし穴

**HTML エンティティ エンコーディング不一致**:
- Python代入値: `detail_url = "report.aspx?id=123&type=report"` （`&`）
- HTML属性値: `href="report.aspx?id=123&amp;type=report"` （`&amp;`）
- CSS セレクタは HTML テキストレベルでマッチするため失敗

**解決策**:
1. ワイルドカード セレクタで全体を取得
2. プログラム的に属性値を比較（エンコーディング対応）

## 今後の活用

このドキュメント内容は、以下の場合に参照される想定：

1. **新しいタイムアウトエラーが発生した場合**
   - まずフレーム参照が有効か確認
   - セレクタロジックが妥当か確認
   - タイムアウト値の変更は最後の手段

2. **CSS セレクタを使う場合**
   - URL パラメータを含む属性マッチは危険
   - ワイルドカード + プログラム的比較を推奨
   - HTML エンティティ エンコーディングを考慮

3. **根本原因分析**
   - 症状（タイムアウト）vs 原因（フレーム/セレクタ）の区別
   - ログから「Frame refreshed」メッセージを確認
   - セレクタ失敗時はプログラム的比較への転換
